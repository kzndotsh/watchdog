# Configuration reference

**What this is:** every environment variable Watchdog reads: what it does, its default, whether it is required, whether it is a secret and which entrypoint reads it.  
**What this is not:** a setup walkthrough ([`self-host`](../../how-to/self-host.md), [`local-dev`](../../how-to/local-dev.md)) or the Cap API keys, which live in the Settings vault.

Generated by `pnpm generate:env` from the env metadata in `packages/env/src` (each field's `.meta()` and `reference.ts`). Do not edit by hand: `pnpm check:env` fails when this file or `env.example` is stale. `env.production.example` is hand-maintained (it is the compose file's environment), and the same check fails when it lists a variable that is not below or omits one the app validates.

## How to read it

- **Required** means startup fails without it. `web` and `worker` validate the same schema, so both containers need every required variable, even one only the web app uses.
- **Secret** variables are written blank in `env.example` and must never be logged or committed.
- **Used by** names the entrypoint that reads the variable: `web` (the app and API), `worker`, `cli` (`wd`), `migrate` (the container's migrator), `site` (the marketing site) or `compose` (only `docker-compose.prod.yml` reads it).
- **Placeholders and short secrets are refused at startup.** `BETTER_AUTH_SECRET` and `WD_MASTER_VAULT_KEY` need at least 32 characters and may not be a known placeholder (`change-me...`, `secret`, `password`, ...); `S3_SECRET_KEY` may not be a placeholder, nor the development default when `NODE_ENV` is `production`. The error names the variable. Generate a value with `openssl rand -base64 32`.
- An empty value counts as unset.

## Database

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `DATABASE_URL` | Postgres connection URL of the application role (watchdog_app): data privileges only, no DDL, no ownership. The web app and worker connect with it. The password in it is a secret. | none | yes | yes | web, worker, migrate |
| `DATABASE_URL_MIGRATE` | Connection URL of the owner role, which owns the schema: migrations, the first-admin command and vault key rotation run as it. Falls back to DATABASE_URL, which then must own the schema (a single-role setup without the privilege split). | none | no | yes | migrate |

## Case Export

| --- | --- | --- | --- | --- | --- |

## Worker lanes

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `WD_WORKER_QUICK_CONCURRENCY` | How many quick lookups run at once (Caps that make one provider call, like DNS, WHOIS, IP and URL lookups). Per worker process; a second worker adds its own slots. Each running Job can hold a database connection, and the worker's pool has 10: the worker refuses to start when the three lane settings sum to more than 8 (the pool minus 2 kept for its own loops). Applies to the quick lane only. | `4` | no | no | worker |
| `WD_WORKER_HEAVY_CONCURRENCY` | How many heavy Jobs run at once (Caps that parse stored Evidence, Caps flagged slow, and large Case exports). Per worker process; a second worker adds its own slots. Each running Job can hold a database connection, and the worker's pool has 10: the worker refuses to start when the three lane settings sum to more than 8 (the pool minus 2 kept for its own loops). Applies to the heavy lane only. | `2` | no | no | worker |
| `WD_WORKER_ACT_CONCURRENCY` | How many action Jobs run at once (Caps that change something at a provider, like submitting a URL to an archive). An action Job is never run twice: if its worker dies mid-run, reconcile fails it and you start it again. Per worker process; a second worker adds its own slots. Each running Job can hold a database connection, and the worker's pool has 10: the worker refuses to start when the three lane settings sum to more than 8 (the pool minus 2 kept for its own loops). Applies to the act lane only. | `2` | no | no | worker |

## Job logs

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `WD_JOB_LOG_MAX_LINES` | Most log lines one Job keeps. Past it the Job's log ends with a truncation marker and later lines are dropped (the Job still runs). Lines are also cut to 1000 characters. | `1000` | no | no | worker |
| `WD_JOB_LOG_MAX_KB` | Most kilobytes of log text one Job keeps, with the same truncation marker as the line limit. Each save rewrites the Job's log, so a high value costs database writes on a chatty Cap. | `128` | no | no | worker |
| `WD_JOB_LOG_FLUSH_MS` | How often, in milliseconds, a running Job's new log lines are saved and pushed to open Job pages. A Job saves at most once per interval however many lines it logs, and once more when it ends. | `1000` | no | no | worker |

## Case retention

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `WD_CASE_RETENTION_DAYS` | Days a deleted Case stays restorable (owners and admins can restore it from Deleted Cases). After that the worker purges it for good: the Case, its Graph and history and its files are erased and only the deletion record remains. ## Job start limits

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `WD_JOB_START_WINDOW_SECONDS` | Length, in seconds, of the fixed window Job starts are counted in (per organization and per API key). The count resets when a window ends; a refused start says how many seconds remain. A window boundary lets a caller use two windows' worth of starts back to back. | `3600` | no | no | web, worker |
| `WD_JOB_START_LIMIT_ORG` | How many Jobs an organization may start per window (Cap runs, Playbook runs, retries and Case exports that run as a Job; every Playbook step after the first is part of its run and not counted). Over it, a start is refused with HTTP 429 and the code job_start_limited. An instance admin can set a different limit for one organization, and an owner or admin can lower it, through the API. | `600` | no | no | web, worker |
| `WD_JOB_START_LIMIT_KEY` | How many Jobs one API key may start per window, counted next to the organization limit (a start must fit both). Keeps one runaway agent from using the whole organization's budget. An owner or admin can set a different limit for one key through the API. | `120` | no | no | web, worker |

## Breach Caps

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `WD_ENABLE_BREACH_CAPS` | Enable the breach Caps (HIBP, Hudson Rock, DeHashed, Snusbase), which query breach and leak corpora about people; DeHashed and Snusbase can return recovered plaintext credentials. Off by default: while it is off none of them can be queued or run, the web app shows them disabled and Playbooks that include them cannot start. Turning it on makes you responsible for a lawful basis for the lookups and for each provider's terms; see docs/reference/platform/cap-register.md. Restart web and worker after changing it. | `false` | no | no | web, worker |

## Error reporting

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `WD_ERROR_REPORTING_DSN` | Send server, worker and browser errors to a tracker that speaks the Sentry protocol (Sentry, GlitchTip, Bugsink): its DSN, https://<key>@host/<project>. Unset (the default) sends nothing anywhere; a value that is not a valid DSN leaves reporting off and logs one warning at start. Secrets, request bodies, Evidence content and emails are scrubbed before an error leaves. See docs/how-to/self-host.md. | none | no | yes | web, worker |
| `WD_RELEASE` | Release or version label attached to error reports and exported logs (for example 1.4.0 or a commit SHA), so a report names the build it came from. Unset omits it. | none | no | no | web, worker |

## Log export (OTLP)

| Variable | Description | Default | Required | Secret | Used by |
| --- | --- | --- | --- | --- | --- |
| `WD_OTLP_ENDPOINT` | Export logs from the web app and the worker over OTLP/HTTP: the base URL of an OpenTelemetry Collector, Datadog, Grafana Cloud, Honeycomb or SigNoz (Watchdog adds /v1/logs). Unset (the default) sends nothing anywhere; a value that is not an http(s) URL leaves export off and logs one warning at start. Every record is scrubbed first. May embed credentials, so treat it as a secret. See docs/how-to/self-host.md. | none | no | yes | web, worker |
| `WD_OTLP_HEADERS` | Headers sent with every OTLP request, as comma-separated name=value pairs (for example x-honeycomb-team=KEY or DD-API-KEY=KEY). Usually the API key. Malformed pairs leave export off with one warning. Ignored while WD_OTLP_ENDPOINT is unset. | none | no | yes | web, worker |
| `WD_OTLP_RESOURCE_ATTRIBUTES` | Extra OTLP resource attributes as comma-separated key=value pairs (for example deployment.region=eu,team=osint). service.name, service.version (WD_RELEASE) and deployment.environment are set for you. Malformed pairs leave export off with one warning. | none | no | no | web, worker |
