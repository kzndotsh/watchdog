# Caps boundary, credentials, Intake, Export

**What this is:** Cap SPI vs catalog, credentials, the Intake path, Case Export.  
**What this is not:** Cap id lexicon / D1-D5 ([`caps-lexicon.md`](caps-lexicon.md)), package matrix ([`packages.md`](packages.md)), agent writes ([`../contracts/agent-ingress.md`](../contracts/agent-ingress.md)), identifier collision and invalid-value rules ([`../contracts/custody.md`](../contracts/custody.md)).

## Caps (boundary)

Layering: **SPI** (`@watchdog/caps/sdk`, `packages/caps/src/sdk/`: `defineCapability`, `CapDescriptor` / `toCapDescriptor`, CapContext) is not the **catalog** (`@watchdog/caps`: implementations, registry, playbooks), which is not **tools** (`@watchdog/tools`: dumb helpers with no PatchOp / Graph / Cap types, including producer Zod for DNS/WHOIS/oEmbed reports). Runtime consumers (core, api, web) import the catalog from `@watchdog/caps`; `core` imports the SPI from `@watchdog/caps/sdk`; Cap code inside `packages/caps` uses relative paths. Guidance backed by dependency declarations ([`packages.md`](packages.md)): caps declares no `db` dependency (nothing fails if one is added), and `CapContext` has no DB handle (a type).

- Author only through `defineCapability` / `defineCollectCap` (`packages/caps/src/lib/collect/`), **one folder per Cap** (`network/dns.lookup/`, `evidence/harvest/`; layout in [`packages/caps/AGENTS.md`](../../../packages/caps/AGENTS.md)). Collect Caps call tools helpers from `run`, `safeParse` with the `@watchdog/tools` schemas imported directly from `@watchdog/tools/<domain>`, and map to patches in `interpret.ts`. Do not redefine producer shapes as TS interfaces.
- **`CapDescriptor`** is the serializable projection of a Cap (no `run` / `interpret`): identity, kind/flags, the declared `contacts` and the egress classes derived from them, consumes/produces, credential names, jobPolicy, and Zod-to-JSON-Schema `input` / `inputForm`. `listCapabilities()` returns descriptors for Jobs, CLI and agents. The committed artifact `packages/caps/capabilities.gen.json` comes from `pnpm generate:caps`; never hand-edit. Enforced: CI "CapDescriptor drift" and `capabilities-gen.test.ts`.
- **`run`** returns artifact metadata `{ name, mime, uri, sha256 }[]` only: no Graph writes, no absolute paths, no inline bytes. Durable bytes go through `ctx.uploadArtifact`. `ctx.readArtifact(uri, { maxBytes, reason })` reads an artifact into memory; a Cap that reads user-supplied bytes passes the limit, and an object over it is refused with a `ValidationVendorError` carrying `reason` without being loaded (its declared length is checked first, then the stream is read only up to the limit). CapContext for `run`: `input`, `caseId`, `jobId`, `signal`, `uploadArtifact`, `readArtifact`, `scratchDir`, `getCredential`, `hasCredential`, `log`, optional `evidenceSnapshot`.
- **`interpret(report, opts)`** is optional and pure: `{ patch, summary? }`, with no CapContext or I/O. Core loads the canonical `report.json` and the worker creates the **Proposal** (the patch is not stored on the Job). Process Caps get a packed **EvidenceSnapshot** before `run`; no live Graph reads.
- **`timeoutMs`** (default `DEFAULT_CAP_TIMEOUT_MS`, 120s) is the only place to set timing. It drives `ctx.signal` (the Job fiber's `AbortSignal`), pg-boss `expireInSeconds`, the worker graceful-stop window and stale-`running` reclaim (`capTimeoutMs` in `caps/src/sdk/define.ts`, `capTimeoutCeilingMs` in `caps/src/registry.ts`, `POST_RUN_SLACK_MS` in `core/src/jobs/timeouts.ts`). Guidance: do not hardcode derived timings elsewhere.
- **`jobPolicy`** holds declarative runner hooks: `needsEvidenceSnapshot`, `linkEvidenceFromInput`, `markEvidenceProcessed`, `cacheTtlMs` (ignored for `kind: "act"`). Keep Cap taxonomy out of `executeJob`. A cached result is served only to a Job of the same Cap version: the version is derived from the Cap's code (see the caps `AGENTS.md`), stamped on `jobs.cap_version` at claim, and a mismatch is a miss that the next run overwrites. A Job reclaimed after a deploy caches under the version it was claimed with.
- **`contacts`** is the one network statement a Cap makes (`contact.provider`, `contact.download`, `contact.target`, `contact.dnsZone`, `contact.model`; `[]` for a Cap that stays on the install); a Cap has no `egress` field. The descriptor's `egress` is the list of egress classes derived from `contacts` (`deriveEgressClasses` in `@watchdog/schemas/caps`), and a Job is blocked before it runs unless its Case allows every class the Cap needs (`cases.allowed_egress`). Contract: [`caps-lexicon`](caps-lexicon.md#contacts-and-egress-classes).
- **Cap failures use one taxonomy.** `run` fails with a `@watchdog/tools` vendor tag (`ToolsTag`: `RateLimitedError`, `HttpVendorError`, `ParseVendorError`, `MissingCredentialError`, `ValidationVendorError`, `BlockedTargetError`, `OutboundLimitError`, `UnexpectedToolError`). Each tag has its own stable `code` and derives its message from its fields; tools has no separate error class family and nothing parses a message to pick a class. Core maps each tag to a core tag by tag name in one exhaustive table (`toDomainTag` in `packages/core/src/infra/vendor-errors.ts`: upstream faults become `InternalError`, a missing credential, rejected input or a blocked outbound target becomes `InvalidError`; a response that exceeds a client bound (bytes, time, redirects) becomes `InternalError`), so a Job pipeline fails only with core tags. Abort is `AbortedError`, a defect rather than a typed failure. Tests: `vendor-errors.test.ts` (core, tools).
- **`interpret` failure:** the Job stays `succeeded` with its artifacts; `jobs.interpretError` is set and no Proposal is created.
- **Finding suppression:** before Proposal insert, core drops ops already on the Graph or previously Rejected (fingerprints) and records `jobs.suppressed_count` / `proposals.suppressed_count`. Cache hits set `jobs.from_cache`. Cap `resultSummary` and Proposal `summary` stay Cap-owned prose; do not concatenate "all known" into them.
- **Job-internal artifacts** (`isJobInternalArtifact` and the id constants in `@watchdog/schemas` `job-artifacts`: `report.json`, `evidence-snapshot.json`, `derived.json`, enrich `live.*` / `enriched.md` / `links.json`) never become Case Evidence rows; they stay on the Job `output`.
- **Playbooks are user-initiated.** A Playbook run starts only from an explicit user action in Collect, never automatically from a dump or an Evidence landing (`guidance`: no test asserts it). Only step 0 is queued at start; later steps are created as each Job succeeds.
- LLM helpers live in `@watchdog/ai` (provider + `structuredExtract` + draft Zod); `draftToPatchOps` stays in `@watchdog/caps`. Prompts are Cap-local.

## Cap credentials

Settings stores Cap secrets encrypted (AES-256-GCM) under `WD_MASTER_VAULT_KEY` (required, at least 32 characters and not a known placeholder, validated by `@watchdog/env/server`; format in `vault.ts`). The same vault is exposed over oRPC `GET|PUT|DELETE /credentials`, never returning plaintext: an API key (and `wd credentials list`) can read the slot list, while `PUT` and `DELETE` need a signed-in session (Settings → Credentials). Known slot names: `KNOWN_CREDENTIALS` in `packages/caps/src/known-credentials.ts`.

Rules:

- Caps load secrets only through `ctx.getCredential(name)`. Never read `process.env` for Cap secrets; never put them in `Job.input`, Export or logs. Enforced for declared credentials by fail-closed specs at `startJob` / playbook start and in worker preflight; guidance for everything else (no lint on `process.env` in caps).
- Deploy/boot vars use `env.*` from `@watchdog/env/server`. The CLI parses `WD_API_*` itself in `loadCliEnv()` (lazy, so `wd --help` works without a key).
- **Replacing or losing `WD_MASTER_VAULT_KEY` makes existing ciphertext unreadable; rotating it with `vault-rekey` (all or nothing, [`backup-restore`](../../how-to/backup-restore.md#rotating-the-vault-key)) does not.** `just wipe` keeps `auth` and vault rows. Generate the key with `openssl rand -base64 32` or `openssl rand -hex 32` (see the [configuration reference](configuration.md)), back it up ([`backup-restore`](../../how-to/backup-restore.md)) and restart web and worker after changing it.

`CapabilityDef.credentials` is a list of specs:

| Spec | Meaning |
| --- | --- |
| `{ name }` | Required: the Job fails closed if missing |
| `{ name, optional: true }` | Present-or-skip |
| `{ anyOf: [a, b, …] }` | At least one name must be set (e.g. AI Process providers) |

Process AI resolves `ANTHROPIC_API_KEY` or `AI_COMPAT_API_KEY` (+ optional `AI_COMPAT_BASE_URL`) at run time through these specs.

## Outbound HTTP

Every request a Cap or tool makes goes through one client in `@watchdog/tools/http`: the hardened `fetch` of `OutboundClient` (a URL string or `URL`; a `Request` object is refused), exposed to Effect code as `httpClientLayer` / `toolsHttpClientLayer` (`HttpClient`). Direct `fetch` (also `globalThis.fetch`, `window.fetch`, `self.fetch`), `require`, `node:http(s|2)`, `node:tls`, `node:dgram`, `node:dns`, the connecting APIs of `node:net`, `undici` and `FetchHttpClient` are lint errors in `packages/caps` and `packages/tools` (`eslint/no-restricted-globals`, `no-restricted-properties`, `no-restricted-imports`; `isIP` and type imports stay legal). The explicit allowlist is `http/safe-fetch.ts`, `http/http-client-layer.ts`, `http/outbound-client.ts`, `http/outbound-policy.ts`, `http/egress-tls.ts`, `http/egress-dns.ts` and the client's own loopback-server test. Guarantees, per call:

- **Only public http(s) targets.** A literal IP host, a non-http(s) scheme, `localhost`, a single-label name and the reserved internal suffixes (`.localhost`, `.internal`, `.local`, `.lan`, `.home.arpa`) are refused before a socket opens. A host name is resolved once, **every** returned A/AAAA address is checked, and the call is refused when any one is not publicly routable. The request is sent with the `fetch` of the same `undici` package that supplies the dispatcher, so the hook always applies. The connection `lookup` hook returns the validated addresses to the socket, so nothing is resolved again between the check and the connect. IPv4 refuses unspecified, loopback, private, link-local (cloud metadata), carrier-grade NAT, multicast, reserved and broadcast, documentation and benchmarking ranges. IPv6 is an allowlist: only global unicast `2000::/3` outside `2001::/23` (protocol assignments), `2001:db8::/32` and `3fff::/20` (documentation) is public, and the forms that carry an IPv4 address (mapped, translated, NAT64, 6to4) are judged by that address (`http/blocked-address.ts`).
- **Redirects are followed by the client, not by fetch.** Each hop repeats the checks above, up to `maxRedirects` (default 5). Credentials and custom headers are not forwarded to another origin, and a request body is never re-sent to a different origin (a cross-origin 307/308 with a body fails with `BlockedTargetError`, `reason: "redirect"`). `redirect: "manual"` returns the first 3xx so a caller such as `unshorten` can record the chain; each hop is its own checked call.
- **Bodies are streamed.** The body is read up to `maxBytes` (default 8 MiB) and the connection is released at the limit; the whole body is never buffered first. A response over the limit fails with `OutboundLimitError` (`kind: "bytes"`), or with `truncate: true` returns what was read (`fetchBytesEffect`). A declared `Content-Length` over the limit fails before any byte is read (not checked on a HEAD response). The default 8 MiB cap applies to every call, including JSON vendor calls; a larger call must raise `limits.maxBytes`.
- **A per-call timeout** (`timeoutMs`, default 30 s, headers and body together), separate from the Cap's own timeout and signal. `OutboundLimitError` (`kind: "timeout"`).
- **Pools are a scoped resource.** The undici `Agent` and the optional egress `ProxyAgent` belong to `OutboundClient`, built by `outboundClientLayer` and closed, awaited, when its scope closes: the worker (`provideWorkerLayers`, released after the interrupted Jobs) and the web server's `AppLive` provide it once. In-flight requests get a short grace (5 s) at close and are then aborted; a request made after close is refused. Nothing closes a pool in the background, and no module holds a pool for the life of the process (`toolsHttpClientLayer`, for tests and one-shot scripts, owns its pools for the scope it is provided in).
- **Interruption aborts the request.** Every request runs under the calling fiber: interrupting it (a timed-out or cancelled Job, `JobFibers.abort`) aborts the request in flight and releases its connection, including each hop of `unshorten` and `http-probe`; the Cap's own `AbortSignal` does the same.
- **Every call is recorded per Job.** `httpClientLayer` sits on the Job's `Egress` (`@watchdog/tools/http`), which core builds for each Job over the shared `OutboundClient` (`makeJobEgress`, in the collect stage) and provides around `cap.run`; Cap and tools code is unchanged. Each request adds one `ProviderCall` to the Job's `EgressLedger` (append-only; `drain()` returns the calls so far): method, redacted URL, each redirect hop with its status and wire-attempt count, final status, an allowlisted set of response headers (`content-type`, `content-length`, `content-encoding`, `date`, `etag`, `last-modified`, `server`, `x-request-id`, `cf-ray`, `x-ratelimit-*`, and `location`, redacted; never `set-cookie`), timing, and the body as `stored`, `hashed` (over the per-call 2 MiB or per-Job 16 MiB keep limit), `partial` (the reader stopped, the byte cap cut it or a read failed: the hash covers only the prefix read) or `none`. A body that exactly fills `maxBytes` is complete. The hash covers the bytes the Cap received (the transport has already decoded any Content-Encoding), read as the Cap pulls them, never ahead. Request headers are never recorded and a request body only as a SHA-256. URLs are redacted by value: a secret credential value (8 or more characters, registered when the Cap reads it through `ctx.getCredential`; a slot is a secret unless its `KnownCredential` says `secret: false`, as `AI_COMPAT_BASE_URL` does) shows as `[credential:NAME]` in its raw, percent-encoded and form-encoded forms, and the value of `key`, `apikey`, `api_key`, `token`, `access_token`, `sig`, `signature`, `X-Amz-Signature`, `code`, `state`, `password` (and a few like them) is replaced whatever it is. Tests that are not a Job use `toolsHttpClientLayer` (no ledger) or `unrecordedEgressLayer` / `recordingEgress` from `@watchdog/tools/testing`.
- **A Cap reaches only what it declared.** Core gives each Job's `Egress` the running Cap's `contacts` and the values of the Job input (`egressPolicyFor`, `http/egress-policy.ts`). Every HTTP hop, every DNS name and every TLS peer must be admitted by a contact, or the call is refused with `BlockedTargetError` (`reason: "undeclared"`, or `"seed"` for a download) whose fixed message never names the target, and the refusal is recorded in the ledger as a failed call. The check runs on every redirect hop (`SafeFetchInit.guard`, beside the address checks, which still apply to every hop of an admitted host). A `provider` contact admits its host (and, with `redirects: "any_public"`, any host on a redirect hop); a `target` contact admits the host the input names, any host on a redirect hop, and over DNS or TLS the input's name and the names under it (`anyHost` also admits any first host, for a Cap that makes one call per hop); a `dns` contact admits the names in its zone; a `model` contact is admitted by `llmFetchFor`, not here. A `download` request must be a body-less `GET` of exactly its declared URL: that is the guarantee that no Case data is part of it, and any other request to that host is refused. Its headers are also scanned for the input's values (raw, lower-cased, host-normalized and percent-encoded forms; a value under 4 characters is not scanned), which catches an authoring mistake and proves nothing by itself. `undeclared` and `seed` map to `InternalError` in core, because they are declaration bugs and not caller input; a refused target hop stays `InvalidError`. An `Egress` built without a policy (tests, scripts) admits what the address checks allow.
- **Calls are stored, write-ahead, and linked to the Evidence they produced.** The collect stage gives the ledger an `onCallStart` hook that core points at `provider_calls`: each door (`fetch`, DNS, TLS, model) waits for the request side of a call (id, method, redacted URL, body kind, request-body hash, start time, run id) to be inserted before it sends, so a worker that dies mid-call still leaves its row, which matters most for an action Cap ("we submitted X"). A request row that cannot be saved stops the call (it is not made). When the Cap's run succeeds, every outcome (`provider_call_outcomes`: status, allowlisted headers, hops, timing, failure class, body state) and every raw body is saved before Evidence lands, and a failure to save fails the Job (`InternalError`, fixed message). When it fails or is cancelled the save is best effort under one 5 s budget for the whole tail (save plus flag), and a stop that lands during the success-path save flags the Job too; what could not be saved sets `jobs.provenance_state` to `incomplete` (a stale Job that reconcile fails is flagged too), so a gap never reads as "no calls". A call cut short is saved as outcome `unfinished`. Raw bodies are content-addressed under the Case's blob prefix (`{caseId}/{sha256}/provider-response`, opaque bytes, the provider's content type only in the stored headers) up to the keep limit (per call 2 MiB by default, or the Cap's `rawResponse: { keep: { maxBytes } }`; per Job 16 MiB): over it the hash and size stay and the body is withheld (`body_reason` `over_limit` or `over_job_budget`). A `breach.*` Cap (derived from the id) and every model call store the hash and size only (`hash_only`). `evidence_provider_calls` links Evidence to the calls of the run that produced it, in the transaction that lands it; Evidence a cache hit lands anew links to the calls of the run the cache came from (`jobs.cache_source_job_id` names it), and reused Evidence keeps the links it has. The in-process feed caches (Feodo, GreedyBear, Tor exits, FireHOL) keep the call that fetched their value; an entry is served only once core has confirmed the call behind it saved (`markCallsSaved`), so a Job whose save failed is never the origin of Evidence, and a Job served from one records a call with outcome `served_from` naming the original (`served_from_call_id`, a soft reference because the cache is shared across Cases) and the original's body hash. The three tables are append-only (`AUDIT_TABLES`: the application role can insert and read, never update, delete or truncate), Case-scoped by composite keys, cascade with the Case, and a purge counts the calls, outcomes, links and raw bodies it erased ([`custody`](../contracts/custody.md#deletion-and-retention)). The record proves what the stored body is (its hash is of the bytes the Cap received), not what the provider sent on the wire.
- **Typed failures.** A refused target is `BlockedTargetError` (`code: "blocked_target"`, fixed message per reason that never echoes the URL; core maps a refused caller target to `InvalidError`). A name that resolved to a refused address (`reason: "resolved"`) carries the same text as any unclassified failure and maps to `InternalError`, so a response never reveals how a name resolves; `reason` keeps the detail for logs. Proxy misconfiguration (`reason: "proxy"`) is also `InternalError`. Limits are `OutboundLimitError` (`code: "outbound_limit"`). Per-call overrides: `limits` on `fetchJson*Effect`, `withOutboundLimits(effect, limits)`, `maxBytes` on `fetchBytesEffect`. The raw TLS audit uses the same address policy (`safeSocketLookup`).

**Egress proxy.** `WD_EGRESS_PROXY` (optional http(s) URL, validated in `@watchdog/env/server`; parsed by the one `parseEgressProxyUrl` in `@watchdog/env/egress-proxy` for both the schema and the client; tools reads it from the process environment because it cannot load the validated server env) routes all Cap traffic through one proxy; unset means direct. A set but unusable value fails every request closed with `BlockedTargetError` (`reason: "proxy"`) rather than going direct. With a proxy the proxy connects, so connection-time address pinning cannot apply. On every hop the scheme, literal-IP and host-name checks still run locally, and the name is also resolved locally as a best effort and refused when any answer is not public; a local resolution failure proceeds to the proxy (it may resolve names this host cannot). The byte cap, timeout and header handling are unchanged. The operator owns address filtering at the proxy. The raw TLS audit opens a socket the HTTP proxy cannot carry, so with a proxy set it fails closed (`BlockedTargetError`, `reason: "unproxied"`) instead of connecting directly. The proxy URL (it may hold credentials) is never logged or echoed.

**DNS, TLS and model calls go through the Job's `Egress` too.** `Egress` has three more doors beside `fetch`, each recorded as a `ProviderCall` with a `transport` and a `bodyKind` that says what the hash covers:

- `Egress.resolve({ type, name }, signal)`: every resolver call of the DNS Caps and tools (`dns.*`, `ip.lookup`, `email.lookup`, the Cymru hash registry). It records `transport: "dns"`, `method` the record type, `url` `dns:<name>?type=<rrtype>`, `status` the response code (0 NOERROR or no data, 2 SERVFAIL, 3 NXDOMAIN) and a body of `bodyKind: "dns_answer_json"`: the parsed answer as canonical JSON (sorted keys, no whitespace), not a wire message. Names go through the tools host normalizer (`normalizeHost`: case, trailing dot, scheme, port), and service labels such as `_dmarc` are allowed; a PTR query is named by the address it reverses. DNS lookups do not use the egress proxy. The resolver itself (`http/egress-dns.ts`) is private to the egress module and is cancelled when the signal aborts or the fiber is interrupted.
- `Egress.tlsConnect(target)`: the TLS audit's handshake (`http/egress-tls.ts`). It records `transport: "tls"`, `url` `tls://<host>:<port>`, `status` 0 once the handshake completed, and a body of `bodyKind: "tls_peer_chain_der"`: the DER of each certificate the peer sent, leaf first, concatenated. It fails closed under an egress proxy and for a host the address policy refuses (`BlockedTargetError`), and records both refusals.
- `Egress.llmFetchFor(origin)`: the `fetch` a model call uses, after the Cap resolved its provider once (`evidence.extract.ai` passes it to `createWatchdogModel`). Admitted origins: the fixed Anthropic host, any public origin (through `OutboundClient`, so its address guard, proxy and limits apply), and a private or loopback origin only when the operator listed it in `WD_AI_PRIVATE_ORIGINS` (default `http://127.0.0.1:8080`, `none` for no entry). A listed private origin may bypass the private-address block and never uses the proxy; it still allows http(s) only, a byte cap and a deadline. For every model call a redirect is refused (`redirect: "error"`), a request to any origin but the admitted one is refused, and the response is recorded hash-only (`reason: "hash_only"`, no stored body). A refused origin is `BlockedTargetError` (`reason: "ai_origin"`): a fixed message that names the setting and never echoes the URL or a credential, mapped to `InvalidError` because the endpoint is the member's own vault setting (`AI_COMPAT_BASE_URL`, `secret: false`, so a recorded URL names the real destination). Tests: `packages/tools/src/http/__tests__/safe-fetch.test.ts` (a loopback test server, an injected resolver and a local proxy; no internet) and `blocked-address.test.ts`.

## Intake

Path: **Dump → Enrich (URL) → Process → Triage Accept** (a human sets confidence).

- **Process** → Cap Job `evidence.harvest` (deterministic) or `evidence.extract.ai` (LLM). Core packs an **EvidenceSnapshot** (falling back to the Enrich Job's `enriched.md` for URL-only dumps), the Cap fills a **ProcessExtractDraft**, `interpret` yields a **Proposal** when an Entity is attached. `processedAt` is set when interpret says so (a Proposal, or an empty extract with text present), not when the signal needs an Entity or a URL dump still has no text (Enrich first). OpenAPI `evidence.process` / `wd evidence process` (`--ai` for extract) run the same glue.
- **Enrich** (URL dumps) → Cap Job `network.url.enrich` (live + Wayback). Run-only: no `interpret`, no Proposal. Intake glue `enrichUrlEvidence` reads `sourceUrl` and starts the Job (`evidence.enrich` / `wd evidence enrich`). Markdown pipeline: prefer `Accept: text/markdown` from the origin, else local HTML-to-md; do **not** proxy investigation URLs through `markdown.new` (OPSEC; guidance). Artifacts stay on the Job; `enriched.md` is page prose plus `## Outbound links` with a `links.json` sidecar.
- **File dump:** client SHA-256 → `presignUploadFn` → PUT to object storage → `confirmFileUploadFn` (the server reads the stored object, computes the SHA-256 itself and refuses a mismatch with the declared hash, size or type; the Evidence stores the server's hash: [`custody`](../contracts/custody.md#evidence-uploads)). Same loop via OpenAPI (`evidence.presign` / `confirmFile`) and `wd evidence file`. Paste hashes server-side via `uploadArtifact`. Max 100 MB per file (`MAX_UPLOAD_BYTES` in `@watchdog/schemas`). If confirm fails, the uploaded object stays in the bucket with no Evidence row until the worker's orphan sweep deletes it (24 hours after the presign). A URL dump is metadata only until Enrich.
- Lexicon: **Collect** = dump + Cap/Job runs (`/cases/$caseSlug/collect`); **Triage** = the Accept gate (`/cases/$caseSlug/triage`). Do not compound "Intake Process" as a type.

## Case Export

The worker and API write a live markdown shadow under `export/<organization-id>/<case-slug>/` (override with `WD_EXPORT_DIR`). The directory is gitignored and regenerable: a projection, not the SoT (case slugs are unique per organization; a pre-multi-org `export/<case-slug>/` folder is stale). A Case rename regenerates the slug and best-effort renames the directory, then `scheduleCaseExportEffect`. Agents use the authenticated file routes `GET …/cases/{id}/export.zip` and `…/entities/{slug}/export.md` via `wd export zip|md`. `export.zip` streams the archive as it is built (Evidence is read with bounded concurrency, so memory does not grow with the Case). Above `WD_EXPORT_INLINE_MAX_MB` of Evidence it answers 202 and a system Job (`system.case_export`) builds the zip on the worker into object storage under `exports/`; the Job's `succeeded` entry in Recent activity is the notification, and `GET …/cases/{id}/exports/{jobId}` is the download link, which expires `WD_EXPORT_LINK_TTL_HOURS` after the archive is stored (the worker then deletes the archive). The archive is a projection like the shadow folder: it is built from the Graph, never read back into it. Details: `@watchdog/core` `infra/export-sync`.

## Controlled vocab

Platform enums, identifier platforms, identifier validation, `PatchOp`, `EvidenceSnapshot`, fingerprints and Cap/Job artifact id constants live in `@watchdog/schemas`. UI and domain code import them from there directly; do not re-export through `domains/*/types.ts` or `*.functions.ts` (guidance). Ownership map: [`types.md`](types.md).
