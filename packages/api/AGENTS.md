# API package (`@watchdog/api`)

> Scope: `packages/api` (inherits root [AGENTS.md](../../AGENTS.md) unless noted)

oRPC procedures + OpenAPI contract for `/api/v1`. Procedures call `@watchdog/core`; there is no SQL here (api has no `@watchdog/db` dependency, so its integration tests call core services and seed through `@watchdog/test-db`).

## Commands

| Task                    | Command                                       |
| ----------------------- | --------------------------------------------- |
| Typecheck               | `pnpm --filter @watchdog/api typecheck`       |
| Integration tests       | `pnpm test:integration`                       |
| Export OpenAPI contract | `pnpm --filter @watchdog/api export-contract` |
| Regen HTTP client       | `pnpm generate:client`                        |

## Rules

| Rule | Enforced by |
| --- | --- |
| After any route/input change: export contract → `pnpm generate:client`, commit `packages/client/src/generated/*` | CI drift job (`ci.yml`) |
| Procedures taking `caseId` pass the actor's `organizationId` into core; a foreign or missing Case is `not_found`, with no distinct "wrong org" signal. Org resolution lives in `@watchdog/auth` (`createApiContext`); `authed` throws FORBIDDEN without an organization, so procedures never resolve org themselves | `src/__tests__/org-isolation.int.test.ts`; `org-isolation-coverage.test.ts` fails when a router procedure is in neither the attack list nor its reasoned allowlist |
| Unknown errors are 500, not 400. `InternalError` maps to `INTERNAL_SERVER_ERROR` with the fixed message `"Internal server error"`; its `reason`/`cause` go only to the request log (`peekRequestLogger`). `InvalidError` stays 400 for caller-fixable input; `graph.write` id/slug collisions are `ConflictError` (409); a Graph update at an out-of-date row `version` is `StaleVersionError` (409, `data.code: "stale_version"` with `entity`, `id`, `currentVersion`; update inputs require `expectedVersion`, reads and results return `version`, [`custody`](../../docs/reference/contracts/custody.md#optimistic-concurrency)) | `map-domain-error.test.ts` |
| Every mapped error, and every validation (input or output), unrecognized-defect or bare `FORBIDDEN` error oRPC raises, carries `data.code`, declared by `apiErrorMap` (`error-map.ts`, registered once on the base builder in `os.ts`); `UNAUTHORIZED` has no `data` and is outside the map. A new transport code or `data` field changes the map, `toOrpcError`, and the regenerated client in one change; mapped errors are `defined: true`; `withStableCode` supplies or corrects the code for the errors oRPC raises itself | `error-map.test.ts`; `packages/client/src/__tests__/error-code.types.test.ts` |
| The error `data` enums that grow (`entity`, `requiredScope`, `scope`) are made `x-extensible-enum` in the generated spec by `markExtensibleEnums` (`openapi.ts`), so oasdiff does not call a new value breaking; add a new growing enum to `EXTENSIBLE_ERROR_DATA_PROPERTIES`. A Job start refused by a limit is `JobStartLimitError` (`job_start_limited`), mapped to `TOO_MANY_REQUESTS` (429) with `data: { code, scope, limit, windowSeconds, retryAfterSeconds }` (`apiErrorMap.TOO_MANY_REQUESTS`; a third transport code, so the client, the contract and `error-code.types.test.ts` change with it). `Retry-After` is set from the error by the base middleware in `os.ts` through `context.resHeaders` (`setRetryAfter`, `retry-after.ts`), which exists only when the handler has `ResponseHeadersPlugin`: the web handler adds `responsePlugins()`; an in-process client has no header. A route outside the router answers its refusal with `jobStartLimitResponse`. `organization.getJobStartLimits` (`cases:read`) and `organization.setJobStartLimit` (`sessionAuthed`: owner or admin, instance admin to raise the organization's limit above the default) are the limits' surface ([`job-start-limits`](../../docs/how-to/job-start-limits.md)) | `error-map.test.ts`; `retry-after.test.ts`; `procedures/__tests__/job-start-limits.int.test.ts` |
| Case-id inputs use the brand schemas (`trimmedCaseIdSchema` in the shared input schemas, `optionalCaseIdSchema` for optional ones), so the id is a `CaseId` once parsed; output schemas (`schemas.ts`) use `caseIdSchema` for Case ids too, so oRPC clients, web server functions and the CLI infer `CaseId` from `z.output` (ADR-0003: no re-parse at the edge, `.brand()` is type-only). `z.input` stays a plain string, so the OpenAPI contract and `packages/client/src/generated` are unchanged. Procedures pass `context.actor.organizationId` (an `OrganizationId`) and `input.caseId` straight to core | `pnpm typecheck` |
| Name nested wire objects in `schemas.ts` (e.g. `identifierCollisionSchema`); no anonymous inline Zod on the wire. Do not leak DB rows or drizzle types | guidance |
| Credentials procedures expose vault **slots** only, never plaintext | guidance |
| `ready` (`src/procedures/ready.ts`) is the readiness probe: `GET /ready`, 200 with the report or 503 as a `SERVICE_UNAVAILABLE` error whose `data` is the same `{ ok, database, storage }` report (oRPC cannot pick a success status per response). It is the one error outside `apiErrorMap` and carries no `data.code`; the statuses are fixed reason codes (`timeout`, `unreachable`), never driver text. It is built by `makeReady(run)` so tests pass `runAppWith(layer)` instead of mocking `runtime`; production uses `makeReady(runApp)`. `health` stays dependency-free | `src/procedures/__tests__/ready.test.ts`; `@watchdog/core` `readiness*.test.ts` |
| Every `authed` procedure declares the API key scope it needs with `.meta({ scope })` (typed `ApiMeta` in `src/os.ts`; `graphChildWrite` carries `graph:write`, `sessionAuthed` carries `"session"`, `pub` carries `"public"`). One middleware in `authed` enforces it for keys only, before input validation: a missing scope is `FORBIDDEN` with `data.code: "insufficient_scope"` and `data.requiredScope` (`src/scope.ts`, `error-map.ts`), a session passes, and a key reaching a procedure that declares none is refused. Scopes and the shared `requireScope` for routes outside the router live in `@watchdog/schemas` (`src/api-scopes.ts`); classification: [`agent-ingress`](../../docs/reference/contracts/agent-ingress.md#key-scopes) | `src/__tests__/org-isolation-coverage.test.ts` (fails when a procedure declares no scope); `src/__tests__/scope-enforcement.test.ts`; the matrix's key-scope dimension, derived from each procedure's declared scope: `src/__tests__/scope-matrix.test.ts` (refusals) and `scope-matrix.int.test.ts` (allowed, write implies read) |
| Procedure inputs are bounded: every `z.string()` / `z.array()` in an input schema (the `@watchdog/schemas` schemas and any inline `.input(...)`) carries a named limit (`NAME_MAX` ... `ARRAY_MAX`, [`types.md`](../../docs/reference/platform/types.md#input-limits)); a value over it is a 400 with `data.code: "invalid"`. `.output(...)` schemas are exempt | `watchdog/bounded-input-schema` (`oxlint.config.ts`); `packages/schemas/src/__tests__/input-limits.test.ts` |
| List procedures are paged: input `{ cursor?, limit }`, output a named page schema in `schemas.ts` (`listPageSchema(item)`: `{ items, nextCursor, total }`; `pageSchema` only for the two legacy feeds, `activity.listRecent` and `history.list`); a bare array output is allowed only for the bounded lists in `pagination-coverage.test.ts`. Page size is capped (`PAGE_LIMIT_MAX`), a foreign or malformed cursor is a 400 `invalid`, and every list keeps its `cases:read` scope. A declared list (ADR-0007, every `LIST_DEFS` member: `evidence.list`, `identifiers.list`, `entities.list`, `cases.list`, `cases.listDeleted`, `jobs.listForCase`, `graph.listWrites`, `claims.list`, `events.list`, `questions.list`, `edges.list`, `proposals.listForCase`, `collect.list`, `tasks.list`) takes its declaration's `input` (`.input(evidenceList.input)`), returns `listPageSchema(item)` (`total` on the first page), passes the parsed input to its core service whole, and is the one procedure for that list (one Entity's Identifiers are `identifiers.list` with `entityId`), except the projections (`PROJECTIONS` in `pagination-coverage.test.ts`): `evidence.pickerPage` and `entities.pickerPage` (the same `input` and binding with the picker's slim columns, #566, #573) and `proposals.queuePage` (row fields, no patch), each a second procedure so the list's wire type stays one fixed record; a reused cursor is a 400 `cursor_stale`. Every other paged procedure is listed in `NOT_DECLARED` with its reason. Rows by id: `evidence.get`, `evidence.getMany` (picker items: title parts, no body), `entities.matchNames` (`GET /cases/{caseId}/entities-by-names`: the Entities pasted names may mean, at most `ENTITY_NAME_LOOKUP_MAX`), `identifiers.getMany`, `claims | events | questions | edges.getMany`, `entities.getMany` (`GET /cases/{caseId}/entities-by-ids`: under `/entities/`it would shadow an Entity slugged`by-ids`) | `src/__tests__/pagination-coverage.test.ts`; `src/__tests__/pagination.int.test.ts`; `src/__tests__/scope-matrix.test.ts` |
| Procedures in `src/procedures/` are built from `authed` (or `graphChildWrite`); the public builder `pub` (or a raw `os`) needs an adjacent `// public: <reason>` comment (only `health` and `ready` have one) | `watchdog/procedure-must-be-guarded` (`oxlint.config.ts`) |

## Gotchas

- `toOrpcError` maps `DomainTag` via `Match.tagsExhaustive`; run Effects through `runApp`. `AppLive` is `Db.owned` (the one owner of the Postgres pool: disposing `appRuntime`, including the dev reload hook, ends it; Better Auth borrows the same pool through `sharedDb()`, see `apps/web/AGENTS.md`) plus the producer `JobQueue` Layer, the `Vault` Layer and the `BlobStore` Layer ([ADR-0002](../../docs/adr/0002-effect-services-and-layers.md) phases 2-3): `runApp` accepts `R = Db | JobQueue | BlobStore | Vault` (pg-boss starts lazily on the first enqueue; the S3 client is built once and destroyed when the runtime is disposed), and tests override with `runAppWith(layer)(effect)` (e.g. `Db.layerOf(spy)` from `@watchdog/core/infra`, `recordingJobQueue().layer` from `@watchdog/core/jobs`, `recordingBlobStore().layer` from `@watchdog/core/blob`, `fakeVault(...).layer` from `@watchdog/core/vault`). Core reaches the database only through the `Db` service, the queue only through `JobQueue` and object storage only through `BlobStore` and credentials only through `Vault`.
- Runtime lifetime: `appRuntime = makeAppRuntime(AppLive)` (`runtime.ts`) disposes the runtime (producer pg-boss stop, pool and S3 client release) on a Vite SSR full reload (`import.meta.hot.on("vite:beforeFullReload")`: the SSR module runner does not call `hot.dispose` handlers on a full reload, measured on Vite 8) and on a module-level HMR update, so `vite dev` does not accumulate producer pools; `dispose` is idempotent and a runtime that never ran builds nothing. There is deliberately no production shutdown hook: the built web server installs no signal handler and the producer holds no handlers or queued work, so adding one would only change the server's exit behavior; if the server gains a shutdown hook, call `appRuntime.dispose()` there. Dev only: after a dispose, an importer that Vite does not re-evaluate keeps the disposed runtime (its calls fail) until the dev server restarts. Tested in `__tests__/runtime-dispose.test.ts` (fake driver, `makeJobQueueLayers`).
- Logging: shared middleware stamps ids from input, so do not call `context.log?.set` per handler. `ApiContext.log` comes from `peekRequestLogger`.
- Prefer the evidence verbs (`POST …/process`, `…/enrich`) over `jobs.start` for Harvest/Extract/URL Enrich so dedupe and URL-assert stay in one place.
- `evidence.listProviderCalls` and `jobs.listProviderCalls` return `{ provenance, calls, isTruncated, cacheHits }`, an envelope bounded by `PROVIDER_CALL_LIST_MAX` rather than a page (a Job makes a handful of calls, and `provenance` has to travel with the list). The raw response download is a file route on web (`GET /api/v1/cases/{caseId}/provider-calls/{callId}/response`), an attachment of generic bytes; see [`custody`](../../docs/reference/contracts/custody.md).
- Case Export zip/md are authenticated file routes on web, not oRPC; the CLI uses raw `fetch` + `x-api-key`. OpenAPI security accepts Bearer, `x-api-key`, or the session cookie.
