# Tools package (`@watchdog/tools`)

> Scope: `packages/tools` (inherits root AGENTS.md)

Dumb HTTP / DNS / WHOIS / CT / breach / threat helpers: raw fetch/parse output only. No Graph, Cap types, or DB (held by `package.json`). Caps orchestrate these in `run` and pass their own OPSEC UA/limits as params.

## Commands

| Task       | Command                                   |
| ---------- | ----------------------------------------- |
| Typecheck  | `pnpm --filter @watchdog/tools typecheck` |
| Unit tests | `pnpm test:unit`                          |

## Rules

- **Import via per-domain subpaths** (`@watchdog/tools/{archive,breach,cache,ct,dns,errors,file,html,http,identity,network,parse,threat,tls,wayback,whois}`), each declared in `package.json` `exports` and backed by `src/<domain>/index.ts`. There is no root import: the bare `@watchdog/tools` is not exported, and `check:boundaries` fails an undeclared specifier with the list of public subpaths. A new vendor export goes in its domain `index.ts`. Guidance.

- **Producer Zod + inferred types live here**, next to the fetch/parse (`dns/schema.ts`, `whois/schema.ts`, `http/oembed.ts`, per-vendor snapshots). Caps import them from the domain subpath (`@watchdog/tools/dns`, `/whois`, `/http`, …) for `safeParse` (no Cap-local re-export); do not duplicate shapes as TS interfaces in Caps. Guidance.
- Vendor clients export `*Effect` only. Every network request goes through the one client in `src/http` (`safeFetch`, as `toolsHttpClientLayer` for Effect code); a direct `fetch`, `node:http(s)`, `undici` or `FetchHttpClient` is a lint error (only `http/safe-fetch.ts`, `http/http-client-layer.ts` and tests are exempt). The client validates every resolved address and redirect hop, streams with a byte cap, times out per call and honours `WD_EGRESS_PROXY`: contract in [`caps-boundary`](../../docs/reference/platform/caps-boundary.md#outbound-http). Do not add a per-call URL or host guard: pass `limits` (`maxBytes`, `timeoutMs`, `maxRedirects`, `truncate`) when a call needs different bounds. A tool that opens a non-HTTP socket (`tls/audit`) uses `assertAllowedHost` and `safeSocketLookup` from `http/outbound-policy.ts`. HTTP helpers (`fetchJson*Effect`, `fetchBytesEffect`) require `HttpClient` in `R`: provide `toolsHttpClientLayer` once at the Cap `run` / collect / test root, not per request. `http-probe` and `unshorten` call `safeFetch` directly (they need the per-hop response, HEAD to GET), wrapped in `Effect.tryPromise` with `mapToolsCatch`.
- Tagged vendor failures live in `src/errors/tagged-errors.ts` (`vendor-errors.ts` has the short constructors; `BlockedTargetError` and `OutboundLimitError` are raised by the outbound client). Each tag has a unique `code` and a defined `message`: derived from its fields, except `UnexpectedToolError` (fixed text) and `ValidationVendorError` (the message you pass). Tools has no other error family: throw or return a tag. `mapToolsCatch` classifies by class only (never by message text): tags pass through, `AbortedError` and abort-like errors are rethrown as defects, and any other non-tag `Error` becomes `UnexpectedToolError` (a server fault: core maps it to `InternalError`, 500, original kept as `cause`), so a tool that rejects caller input must throw `ValidationVendorError` itself. A `ValidationVendorError` message reaches clients (`InvalidError`, 400) and Job failure text: write a fixed sentence. Its `cause` is logged (API request log, `logJobFailureCause`), so it holds upstream diagnostics only (an HTTP status, `query_status=...`, an error class; `upstreamDiagnostic` in `@watchdog/tools/errors` keeps a status and withholds free text), never the caller's input (URL, email, IOC, handle: it is already in the Job input) and never free upstream or model text that can echo it. A URL you must log is cut to origin plus path first (no userinfo, query or hash); no helper exists yet, so prefer not logging it. This follows the log contract in `docs/reference/contracts/evlog.md`. Core maps tags to core tags by tag name (`toDomainTag`). Never parse a message to recover a tag.
- Shared parse helpers stay Cap-agnostic: Caps choose how to map results into PatchOps.
- Tests: Effect programs use `@effect/vitest` `it.effect` with `Effect.provide(toolsHttpClientLayer)`; pass `retry: false` only when stubbing a single fetch. The client's own tests build `createSafeFetch({ resolve, isBlocked })` against a loopback server (the test policy lets only the server's address through); production code only ever uses the exported `safeFetch`. The client sends through the `fetch` of the same `undici` package as its dispatcher (never the runtime's built-in one), so MSW and `vi.stubGlobal("fetch")` would not see it: `packages/tools/vitest.undici-fetch-seam.ts` (a shared setup file) routes that one call to `globalThis.fetch`, and `safe-fetch.test.ts` opts out with `vi.unmock("undici")` to run the real transport against loopback servers. Vendor parse-shape tests run against checked-in `__fixtures__`; mock HTTP via `@watchdog/test-kit/http`.
