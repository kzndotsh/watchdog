# Tools package (`@watchdog/tools`)

> Scope: `packages/tools` (inherits root AGENTS.md)

Dumb HTTP / DNS / WHOIS / CT / breach / threat helpers: raw fetch/parse output only. No Graph, Cap types, or DB (held by `package.json`). Caps orchestrate these in `run` and pass their own OPSEC UA/limits as params.

## Commands

| Task       | Command                                   |
| ---------- | ----------------------------------------- |
| Typecheck  | `pnpm --filter @watchdog/tools typecheck` |
| Unit tests | `pnpm test:unit`                          |

## Rules

- **Import via per-domain subpaths** (`@watchdog/tools/{archive,breach,cache,ct,dns,errors,file,html,http,identity,network,parse,threat,tls,wayback,whois}`), each declared in `package.json` `exports` and backed by `src/<domain>/index.ts`. There is no root import: the bare `@watchdog/tools` is not exported, and `check:boundaries` fails an undeclared specifier with the list of public subpaths. A new vendor export goes in its domain `index.ts`. Guidance.

- **Producer Zod + inferred types live here**, next to the fetch/parse (`dns/schema.ts`, `whois/schema.ts`, `http/oembed.ts`, per-vendor snapshots). Caps import them from the domain subpath (`@watchdog/tools/dns`, `/whois`, `/http`, …) for `safeParse` (no Cap-local re-export); do not duplicate shapes as TS interfaces in Caps. Guidance.
- Vendor clients export `*Effect` only. Every network request goes through the one client in `src/http` (the `OutboundClient` service, as `httpClientLayer` / `toolsHttpClientLayer` for Effect code); a direct `fetch`, `node:http(s)`, `undici` or `FetchHttpClient` is a lint error (the allowlist is in `oxlint.config.ts`; `tls/audit`, `dns/abortable-resolver` and `http/outbound-policy.ts` are the only other files that touch a socket or resolver). The client validates every resolved address and redirect hop, streams with a byte cap, times out per call and honours `WD_EGRESS_PROXY`: contract in [`caps-boundary`](../../docs/reference/platform/caps-boundary.md#outbound-http). Do not add a per-call URL or host guard: pass `limits` (`maxBytes`, `timeoutMs`, `maxRedirects`, `truncate`) when a call needs different bounds. A tool that opens a non-HTTP socket (`tls/audit`) uses `assertAllowedHost` and `safeSocketLookup` from `http/outbound-policy.ts`. HTTP helpers (`fetchJson*Effect`, `fetchBytesEffect`, `http-probe`, `unshorten`) require `HttpClient` in `R`: the connection pools are the scoped `OutboundClient` (`outboundClientLayer`, closed awaited when its scope closes: provided once by the worker and the web `AppLive`), `httpClientLayer` sits on it at the Cap collect root, and `toolsHttpClientLayer` (own pools, for tests and one-shot scripts) at a test root, never per request. A request runs under the calling fiber, so interrupting it aborts the request in flight: use the `HttpClient` (`http-probe` and `unshorten` go through `hop-request.ts`, which maps the failure with `mapToolsCatch`), never a promise that ignores the fiber, and never `void` a promise or leave a `close()` unawaited in `src/http`. `createOutboundTransport` builds the client and its pools for the Layer; `safeFetch` stays exported from `safe-fetch.ts` only for the client's own tests (its pools are never closed, so no production code may use it).
- Tagged vendor failures live in `src/errors/tagged-errors.ts` (`vendor-errors.ts` has the short constructors; `BlockedTargetError` and `OutboundLimitError` are raised by the outbound client). Each tag has a unique `code` and a defined `message`: derived from its fields, except `UnexpectedToolError` (fixed text) and `ValidationVendorError` (the message you pass). Tools has no other error family: throw or return a tag. `mapToolsCatch` classifies by class only (never by message text): tags pass through, `AbortedError` and abort-like errors are rethrown as defects, and any other non-tag `Error` becomes `UnexpectedToolError` (a server fault: core maps it to `InternalError`, 500, original kept as `cause`), so a tool that rejects caller input must throw `ValidationVendorError` itself. A `ValidationVendorError` message reaches clients (`InvalidError`, 400) and Job failure text: write a fixed sentence. Its `cause` is logged (API request log, `logJobFailureCause`), so it holds upstream diagnostics only (an HTTP status, `query_status=...`, an error class; `upstreamDiagnostic` in `@watchdog/tools/errors` keeps a status and withholds free text), never the caller's input (URL, email, IOC, handle: it is already in the Job input) and never free upstream or model text that can echo it. A URL you must log is cut to origin plus path first (no userinfo, query or hash); no helper exists yet, so prefer not logging it. This follows the log contract in `docs/reference/contracts/evlog.md`. Core maps tags to core tags by tag name (`toDomainTag`). Never parse a message to recover a tag.
- Local analyzers (`src/file`) refuse input over a byte cap (`EML_MAX_INPUT_BYTES` 25 MiB, `FILE_MAX_INPUT_BYTES` 64 MiB, in `file/limits.ts`) with a `ValidationVendorError` before parsing, bound MIME structure through `EML_PARSE_LIMITS` (`postal-mime`), and extract with single-pass scans (no backtracking regex on input text; `file/exif.ts`, `file/pdf-info.ts`, `file/eml-extract.ts`). `file/__tests__/bounded.test.ts` holds the generated adversarial inputs and their time budget; keep a new analyzer inside the same bounds. Guidance.
- Shared parse helpers stay Cap-agnostic: Caps choose how to map results into PatchOps.
- Tests: Effect programs use `@effect/vitest` `it.effect` with `Effect.provide(toolsHttpClientLayer)`; pass `retry: false` only when stubbing a single fetch. The client's own tests build `createSafeFetch({ resolve, isBlocked, fetch })` (or `outboundClientLayerWith` with the same deps, `createDispatcher` to spy on pools) against a loopback server (the test policy lets only the server's address through); production code only ever uses the exported `safeFetch`. The client sends through the `fetch` of the same `undici` package as its dispatcher (never the runtime's built-in one; undici 8 stays on HTTP/1.1 via `allowH2: false`, and its egress `ProxyAgent` keeps `proxyTunnel: true`, both set in `safe-fetch.ts`), so MSW and `vi.stubGlobal("fetch")` would not see it: `scripts/vitest/undici-fetch-seam.ts` (a shared setup file: the Cap `run` path provides `toolsHttpClientLayer` itself, so a per-call `createSafeFetch({ fetch })` cannot reach it from a test) routes that one call to `globalThis.fetch` (without the undici `dispatcher`, which the runtime's older bundled undici cannot drive), and `safe-fetch.test.ts` opts out with `vi.unmock("undici")` to run the real transport against loopback servers. Vendor parse-shape tests run against checked-in `__fixtures__`; mock HTTP via `@watchdog/test-kit/http`.
